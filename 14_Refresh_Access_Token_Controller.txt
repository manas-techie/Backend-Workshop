===========================================
REFRESH ACCESS TOKEN CONTROLLER - REVISION NOTES
===========================================

1. WHAT IS IT USED FOR?
-----------------------
Purpose:
- Access tokens have SHORT expiry (e.g., 15 mins - 1 day)
- Refresh tokens have LONGER expiry (e.g., 7-30 days)
- When access token expires, user would need to login again
- refreshAccessToken allows getting NEW tokens WITHOUT re-login

Why Two Tokens?
- Access Token: Used for API requests (short-lived for security)
- Refresh Token: Used ONLY to get new access token (stored in DB)

Real-World Scenario:
```
User logs in → Gets both tokens
↓
Access token expires after 15 mins
↓
Instead of forcing re-login:
Client sends refresh token → Gets new access + refresh tokens
↓
User continues using app seamlessly
```

Security Benefit:
- If access token is stolen → Limited damage (expires quickly)
- Refresh token stored in DB → Can be invalidated on logout
- Refresh token rotated on each refresh → Prevents token reuse

2. HOW IT WORKS (Step-by-Step)
------------------------------

STEP 1: Extract Refresh Token
```javascript
const incomingRefreshToken = req.cookies.refreshToken || req.body.refreshToken;
```
- First checks cookies
- Falls back to request body
- Supports both browser (cookies) and mobile (body) clients

STEP 2: Validate Token Exists
```javascript
if (!incomingRefreshToken) {
    throw new ApiError(401, "Unauthorized Request");
}
```
- No token = Unauthorized
- Returns 401 status

STEP 3: Verify & Decode Token
```javascript
const decodedToken = jwt.verify(incomingRefreshToken, process.env.REFRESH_TOKEN_SECRET);
```
- Uses REFRESH_TOKEN_SECRET (different from access token secret)
- Decodes to get user ID (_id)
- Throws error if token is invalid/expired

STEP 4: Find User in Database
```javascript
const user = await User.findById(decodedToken?._id);
if (!user) {
    throw new ApiError(401, "Invalid refresh Token.");
}
```
- Uses decoded _id to find user
- User might have been deleted

STEP 5: Match Token with Database
```javascript
if (incomingRefreshToken !== user.refreshToken) {
    throw new ApiError(401, "Refresh token is expired or used");
}
```
- CRITICAL SECURITY CHECK
- Compares incoming token with stored token
- Prevents reuse of old/stolen tokens
- If user logged out, stored token is undefined → Mismatch

STEP 6: Generate New Token Pair
```javascript
const { accessToken, newRefreshToken } = await generateAccessAndRefeshTokens(user._id);
```
- Creates fresh access token
- Creates fresh refresh token
- Saves new refresh token to database

STEP 7: Send Response with Cookies
```javascript
return res.status(200)
    .cookie("accessToken", accessToken, options)
    .cookie("refreshToken", newRefreshToken, options)
    .json(new ApiResponse(200, { accessToken, refreshToken: newRefreshToken }, "Access token refreshed"))
```
- Sets new cookies
- Returns tokens in response body (for mobile apps)

3. FLOW DIAGRAM
---------------
```

        ↓

        ↓

        │

        ↓

        │

        ↓

        ↓

        │

        ↓

        ↓

        ↓

```

4. ERROR SCENARIOS
------------------
| Scenario                    | Error Message                    | Status |
|-----------------------------|----------------------------------|--------|
| No token provided           | "Unauthorized Request"           | 401    |
| Invalid/corrupted token     | "Refresh Token not valid"        | 401    |
| Token expired               | "Refresh Token not valid"        | 401    |
| User deleted                | "Invalid refresh Token"          | 401    |
| Token doesn't match DB      | "Refresh token is expired/used"  | 401    |

5. TOKEN ROTATION SECURITY
--------------------------
Each refresh generates NEW refresh token:
```
Login      → RefreshToken_1 stored in DB
Refresh #1 → RefreshToken_1 deleted, RefreshToken_2 stored
Refresh #2 → RefreshToken_2 deleted, RefreshToken_3 stored
```

If attacker steals RefreshToken_1:
- User refreshes → RefreshToken_2 is now valid
- Attacker tries RefreshToken_1 → MISMATCH → Rejected!

6. BUG IN CURRENT CODE
----------------------
Note: There's a destructuring issue:
```javascript
// Current code:
const { accessToken, newRefreshToken } = await generateAccessAndRefeshTokens(user._id);

// But function returns:
return { accessToken, refreshToken };

// Should be:
const { accessToken, refreshToken: newRefreshToken } = await generateAccessAndRefeshTokens(user._id);
// OR change response to use refreshToken instead of newRefreshToken
```
