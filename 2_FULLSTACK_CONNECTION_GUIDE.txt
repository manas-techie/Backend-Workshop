2. USING EXPRESS AS ES MODULE (import syntax)
================================================================================

YOUR CODE (server.js):
import express from "express";    ← ES Module syntax (modern)

VS THE OLD WAY:
const express = require("express"); ← CommonJS syntax (traditional)

HOW IS THIS POSSIBLE?

In your backend/package.json you have:
"type": "module"

This single line tells Node.js:
"Treat all .js files in this project as ES Modules (not CommonJS)."

COMPARISON:
┌──────────────────────────────────────────────────────────────┐
│              CommonJS (Old)      │    ES Modules (New)       │
│──────────────────────────────────│───────────────────────────│
│ const x = require('pkg')        │ import x from 'pkg'       │
│ module.exports = { fn }         │ export { fn }             │
│ Default in Node.js              │ Needs "type": "module"    │
│ Synchronous loading             │ Asynchronous loading      │
│ Dynamic imports easy             │ Static analysis possible  │
│ Used in older projects          │ Modern standard            │
│ "type": "commonjs" (default)    │ "type": "module"          │
└──────────────────────────────────────────────────────────────┘

KEY RULES FOR ES MODULES IN NODE:
• Must add "type": "module" in package.json
• Use import/export instead of require/module.exports
• File extensions may be needed in imports (import x from './file.js')
• __dirname and __filename are NOT available (use import.meta.url instead)
• JSON imports need assertion: import data from './data.json' assert {type:'json'}

WHY USE ES MODULES?
✓ Same syntax as frontend JavaScript (React, Vue, etc.)
✓ Modern standard
✓ Better tree-shaking and optimization
✓ Static analysis for better tooling support
✓ Consistent syntax across frontend and backend

3. HOW AXIOS WORKS (Frontend HTTP Client)
================================================================================

WHAT IS AXIOS?
Axios is a promise-based HTTP client for the browser and Node.js.
It makes HTTP requests (GET, POST, PUT, DELETE) easy and clean.

YOUR FRONTEND CODE (App.jsx):
import axios from "axios";

useEffect(() => {
  axios
    .get("/api/jokes")                    ← Makes GET request to /api/jokes
    .then((response) => {
      setJokes(response.data);            ← response.data = actual JSON data
    })
    .catch((error) => {
      console.error("Error:", error);     ← Handle errors
    });
});

AXIOS vs FETCH (Built-in browser API):
┌───────────────────────────────────────────────────────────────────┐
│  Feature              │  Axios                │  Fetch            │
│───────────────────────│───────────────────────│───────────────────│
│  Auto JSON parsing    │  YES (response.data)  │  NO (need .json())│
│  Error handling       │  Auto for non-2xx     │  Manual check     │
│  Request cancellation │  Built-in             │  AbortController  │
│  Interceptors         │  YES                  │  NO               │
│  Browser support      │  Wide (older too)     │  Modern browsers  │
│  Request timeout      │  Built-in             │  Manual           │
│  Package size         │  ~13KB                │  0 (built-in)     │
└───────────────────────────────────────────────────────────────────┘

AXIOS EXAMPLE WITH fetch EQUIVALENT:

With Axios:
const res = await axios.get('/api/jokes');
console.log(res.data);     ← Already parsed JSON

With Fetch:
const res = await fetch('/api/jokes');
const data = await res.json();    ← Must manually parse
console.log(data);

AXIOS RESPONSE OBJECT:
{
  data: [...],         ← The actual response data (your jokes array)
  status: 200,         ← HTTP status code
  statusText: 'OK',    ← Status text
  headers: {...},      ← Response headers
  config: {...},       ← Request configuration
}

COMMON AXIOS METHODS:
axios.get(url)                  → GET request
axios.post(url, data)           → POST request
axios.put(url, data)            → PUT request
axios.delete(url)               → DELETE request
axios.patch(url, data)          → PATCH request

INSTALLATION:
npm install axios       (in frontend directory)

4. HOW CORS WORKS (Cross-Origin Resource Sharing)
================================================================================

WHAT IS CORS?
CORS is a security feature built into browsers that blocks requests 
from one origin (domain:port) to a different origin.

THE PROBLEM:
Frontend runs on:  http://localhost:5173  (Vite dev server)
Backend runs on:   http://localhost:3000  (Express server)

These are DIFFERENT ORIGINS (different ports = different origin).

When frontend tries to call backend directly:
Browser says: "BLOCKED! You can't make requests to a different origin!"

WHAT IS AN "ORIGIN"?
Origin = Protocol + Domain + Port
http://localhost:5173  ← One origin
http://localhost:3000  ← Different origin (different port!)
https://myapp.com      ← Different origin (different protocol & domain)

CORS ERROR (What you see in browser console):
"Access to XMLHttpRequest at 'http://localhost:3000/api/jokes' 
from origin 'http://localhost:5173' has been blocked by CORS policy"

HOW TO FIX CORS:

METHOD 1: Use cors package (Backend solution)
npm install cors

import cors from 'cors';
app.use(cors());    ← Allow ALL origins (not recommended for production)

// OR allow specific origin:
app.use(cors({
  origin: 'http://localhost:5173'
}));

METHOD 2: Use Proxy (Frontend solution - what YOUR project does)
This avoids CORS entirely by making requests appear same-origin.
(Explained in next section)

WHY CORS EXISTS:
• Prevents malicious websites from stealing data
• Stops unauthorized API access from other domains
• Browser security feature (servers don't enforce CORS)
• Only affects browser requests (Postman/curl bypass CORS)

5. HOW VITE PROXY WORKS
================================================================================

YOUR VITE CONFIG (vite.config.js):
export default defineConfig({
  server: {
    proxy: {
      '/api': 'http://localhost:3000'
    },
  },
  plugins: [react()],
})

WHAT DOES THIS DO?

During development, when your React app makes a request to '/api/jokes':
1. Browser sends request to http://localhost:5173/api/jokes (same origin!)
2. Vite dev server INTERCEPTS this request
3. Vite FORWARDS it to http://localhost:3000/api/jokes (your backend)
4. Backend responds to Vite
5. Vite passes the response back to browser

THE BROWSER NEVER KNOWS IT'S TALKING TO A DIFFERENT SERVER!

DIAGRAM - HOW PROXY WORKS:

WITHOUT PROXY (CORS Error):
┌──────────┐  GET http://localhost:3000/api/jokes   ┌──────────┐
│ Browser  │ ──────────────────────────────────────►│ Backend  │
│ :5173    │ ◄───────── CORS BLOCKED! ──────────────│ :3000    │
└──────────┘                                        └──────────┘
❌ Different origins → Browser blocks it!

WITH PROXY (No CORS Issue):
┌──────────┐  GET /api/jokes    ┌──────────────┐  Forward to   ┌──────────┐
│ Browser  │ ────────────────►  │ Vite Dev     │ ───────────►  │ Backend  │
│ :5173    │                    │ Server :5173 │               │ :3000    │
│          │ ◄────────────────  │ (Proxy)      │ ◄───────────  │          │
└──────────┘  Response data     └──────────────┘  JSON data    └──────────┘
✅ Same origin (:5173 → :5173) → No CORS issue!

WHY '/api' PREFIX?
The proxy config says: "Any request starting with /api → forward to :3000"
This is why your backend routes start with /api/jokes, not just /jokes.

KEY POINT:
• Proxy ONLY works during development (npm run dev)
• In production, there's no Vite dev server running
• That's why your project uses the dist/ folder approach for production
  (more on this in section 8)


6. BEST PRACTICES FOR API WRITING IN BACKEND

YOUR CURRENT API:
app.get('/api/jokes', (req, res) => {
    const jokes = [...];
    res.json(jokes);
});

BEST PRACTICES:

1. USE /api PREFIX FOR ALL ROUTES
   ✅ /api/jokes       (Good - clearly an API endpoint)
   ❌ /jokes           (Bad - could conflict with frontend routes)

2. USE PROPER HTTP METHODS
   GET     /api/jokes       → Fetch all jokes
   GET     /api/jokes/:id   → Fetch single joke
   POST    /api/jokes       → Create new joke
   PUT     /api/jokes/:id   → Update entire joke
   PATCH   /api/jokes/:id   → Update part of joke
   DELETE  /api/jokes/:id   → Delete a joke

3. USE PROPER HTTP STATUS CODES
   res.status(200).json(data)     → Success
   res.status(201).json(data)     → Created
   res.status(400).json(error)    → Bad Request
   res.status(404).json(error)    → Not Found
   res.status(500).json(error)    → Server Error

4. RETURN CONSISTENT RESPONSE FORMAT
   ✅ Good response format:
   {
     "success": true,
     "data": [...],
     "message": "Jokes fetched successfully",
     "count": 5
   }

   ✅ Good error format:
   {
     "success": false,
     "error": "Joke not found",
     "message": "No joke exists with id: 10"
   }

5. USE TRY-CATCH FOR ERROR HANDLING
   app.get('/api/jokes', async (req, res) => {
     try {
       const jokes = await Joke.find();
       res.status(200).json({ success: true, data: jokes });
     } catch (error) {
       res.status(500).json({ success: false, error: error.message });
     }
   });

6. SEPARATE ROUTES INTO FILES
   Don't put all routes in server.js!
   
   // routes/jokeRoutes.js
   import express from 'express';
   const router = express.Router();
   
   router.get('/', getJokes);
   router.post('/', createJoke);
   
   export default router;
   
   // server.js
   import jokeRoutes from './routes/jokeRoutes.js';
   app.use('/api/jokes', jokeRoutes);

7. SEPARATE CONTROLLERS
   // controllers/jokeController.js
   export const getJokes = async (req, res) => {
     try {
       const jokes = await Joke.find();
       res.json({ success: true, data: jokes });
     } catch (error) {
       res.status(500).json({ success: false, error: error.message });
     }
   };

8. VALIDATE INPUT DATA
   app.post('/api/jokes', (req, res) => {
     const { title, content } = req.body;
     if (!title || !content) {
       return res.status(400).json({ error: 'Title and content required' });
     }
     // proceed...
   });

9. USE VERSIONING FOR APIS
   /api/v1/jokes      ← Version 1
   /api/v2/jokes      ← Version 2 (with breaking changes)

10. USE PLURAL NOUNS FOR ENDPOINTS
    ✅ /api/jokes     (plural)
    ❌ /api/joke      (singular)

7. HOW TO HANDLE APIs IN FRONTEND
================================================================================

YOUR CURRENT CODE (App.jsx):
useEffect(() => {
  axios.get("/api/jokes")
    .then((response) => { setJokes(response.data); })
    .catch((error) => { console.error("Error:", error); });
});

STEP-BY-STEP HOW IT WORKS:
1. Component mounts → useEffect runs
2. axios.get("/api/jokes") sends GET request
3. Vite proxy forwards it to http://localhost:3000/api/jokes
4. Express matches the route, sends jokes array
5. .then() receives response → response.data = jokes array
6. setJokes(response.data) updates state
7. React re-renders with jokes data

BEST PRACTICES FOR FRONTEND API HANDLING:

1. USE ASYNC/AWAIT (Cleaner than .then())
   useEffect(() => {
     const fetchJokes = async () => {
       try {
         const { data } = await axios.get("/api/jokes");
         setJokes(data);
       } catch (error) {
         console.error("Error:", error);
       }
     };
     fetchJokes();
   }, []);     ← Empty dependency array! (explained below)

2. ADD LOADING STATE
   const [loading, setLoading] = useState(true);
   const [error, setError] = useState(null);
   
   useEffect(() => {
     const fetchJokes = async () => {
       try {
         setLoading(true);
         const { data } = await axios.get("/api/jokes");
         setJokes(data);
       } catch (err) {
         setError(err.message);
       } finally {
         setLoading(false);
       }
     };
     fetchJokes();
   }, []);
   
   if (loading) return <p>Loading...</p>;
   if (error) return <p>Error: {error}</p>;

3. USE ENVIRONMENT VARIABLES FOR BASE URL
   // Create .env in frontend
   VITE_API_URL=http://localhost:3000/api
   
   // Use in code
   axios.get(`${import.meta.env.VITE_API_URL}/jokes`);

4. CREATE AN API SERVICE FILE
   // src/services/api.js
   import axios from 'axios';
   
   const api = axios.create({
     baseURL: '/api',
     timeout: 5000,
   });
   
   export const getJokes = () => api.get('/jokes');
   export default api;
   
   // In component:
   import { getJokes } from './services/api';
   const { data } = await getJokes();

8. THE "BUILD & SERVE FROM BACKEND" APPROACH
   (What This Project Does)
================================================================================

WHAT HAPPENS IN YOUR PROJECT:

STEP 1: Build the React frontend
  cd frontend
  npm run build        ← Runs "vite build"
  
  This creates a dist/ folder containing:
  dist/
  ├── index.html       ← Main HTML file
  └── assets/
      ├── index-xxxx.js    ← Bundled JavaScript
      └── index-xxxx.css   ← Bundled CSS

STEP 2: Move dist/ folder to backend
  Copy or move the dist/ folder into backend/ directory

STEP 3: Serve dist/ from Express
  In server.js:
  app.use(express.static('dist'));
  
  This tells Express: "Serve all files in dist/ as static files."

STEP 4: Run only the backend
  cd backend
  npm start     ← Starts Express on port 3000

NOW:
• http://localhost:3000 → Serves index.html from dist/ (React app)
• http://localhost:3000/api/jokes → Returns JSON data
• SAME ORIGIN! No CORS issues because both are on :3000

DIAGRAM - HOW IT WORKS:

9. WHY THIS APPROACH IS WRONG / DRAWBACKS
================================================================================

PROBLEMS IN YOUR CURRENT PROJECT:
═══════════════════════════════════

PROBLEM 1: MISSING DEPENDENCY ARRAY IN useEffect
──────────────────────────────────────────────────
YOUR CODE:
useEffect(() => {
  axios.get("/api/jokes").then(...)
});          ← NO DEPENDENCY ARRAY!

WHAT HAPPENS:
• useEffect runs on EVERY render
• Each render → API call → state update → re-render → API call → ∞
• INFINITE LOOP of API calls!
• Your backend gets hammered with requests

FIX:
useEffect(() => {
  axios.get("/api/jokes").then(...)
}, []);      ← Empty array = run only ONCE on mount


PROBLEM 2: MANUALLY BUILDING & COPYING dist/ FOLDER
────────────────────────────────────────────────────
Every time you change frontend code:
1. cd frontend
2. npm run build
3. Copy dist/ to backend/
4. Restart backend server
5. Test changes

This is SLOW, ERROR-PRONE, and PAINFUL!


PROBLEM 3: TIGHT COUPLING OF FRONTEND AND BACKEND
──────────────────────────────────────────────────
• Frontend and backend are mixed into one server
• Can't scale them independently
• Can't deploy them separately
• One crash affects everything
• Different teams can't work independently


PROBLEM 4: NO SEPARATE DEPLOYMENT
──────────────────────────────────
• Can't use CDN for frontend (faster loading)
• Can't use different hosting optimized for each
  - Frontend: Vercel, Netlify, CloudFront (static hosting = cheap/fast)
  - Backend: Railway, Render, AWS EC2 (server hosting)
• Backend server wastes resources serving static files


PROBLEM 5: NO CORS SETUP
─────────────────────────
• Works only because everything is on same origin
• If you ever separate frontend/backend (which you should), 
  it will break immediately
• No cors package installed or configured


PROBLEM 6: HARDCODED DATA IN SERVER
────────────────────────────────────
• Jokes are hardcoded in server.js
• In real projects, data comes from a database
• No separation of concerns (data mixed with routing logic)


PROBLEM 7: NO ERROR HANDLING IN BACKEND
───────────────────────────────────────
• No try-catch blocks
• No error middleware
• No proper status codes
• If something fails, user gets cryptic errors


PROBLEM 8: NO .env FILE
────────────────────────
• Port is kinda handled: process.env.PORT || 3000
• But there's no .env file or dotenv package
• Secrets/config should never be hardcoded


SUMMARY OF WRONG PRACTICES:
┌──────────────────────────────────────────────────────────────────┐
│  Wrong Practice                │  Correct Practice               │

│                                │  package                        │

CORRECT server.js (No dist/ serving):

import cors from 'cors';
import dotenv from 'dotenv';
dotenv.config();

  origin: process.env.FRONTEND_URL    ← Allow only your frontend
}));
app.use(express.json());

// API routes only - no static file serving
app.use('/api/jokes', jokeRoutes);

// Error handling middleware
app.use((err, req, res, next) => {
  res.status(500).json({ success: false, error: err.message });
});

app.listen(process.env.PORT || 3000);
