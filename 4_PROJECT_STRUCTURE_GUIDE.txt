3. FILE-BY-FILE EXPLANATION
================================================================================

ROOT LEVEL FILES:

📄 package.json
   ├─ Purpose: Project metadata and npm configuration
   ├─ Contains:
   │  • Project name, version, description
   │  • List of all dependencies (express, etc.)
   │  • Dev dependencies (nodemon, prettier)
   │  • NPM scripts (start, dev commands)
   │  • "type": "module" → Enables ES6 import/export syntax
   ├─ Key Scripts:
   │  • "start": "node src/index.js" → Production start
   │  • "dev": "nodemon src/index.js" → Development with auto-restart
   └─ Never delete or edit manually except for dependencies

📄 package-lock.json
   ├─ Purpose: Lock exact versions of all dependencies
   ├─ Auto-generated by npm
   ├─ MUST BE COMMITTED to git
   ├─ Ensures everyone uses same dependency versions
   └─ Don't edit manually - let npm manage it

📄 README.md
   ├─ Purpose: Project documentation
   ├─ Should contain:
   │  • Project description
   │  • Setup instructions
   │  • How to run the project
   │  • API documentation
   │  • Contributing guidelines
   └─ Helps other developers understand the project

📄 .gitignore
   ├─ Purpose: Tell git which files NOT to commit
   ├─ Contains:
   │  • node_modules/
   │  • .env (secrets)
   │  • logs, builds, dist/
   │  • OS-specific files
   ├─ Standard Node.js ignores included
   └─ Edit to add project-specific files to ignore

📄 .env
   ├─ Purpose: Store sensitive configuration
   ├─ Contains:
   │  • Database credentials
   │  • API keys/secrets
   │  • Port numbers
   │  • JWT secrets
   │  • Third-party API keys
   ├─ NEVER COMMIT to git (in .gitignore)
   ├─ Only exists on local machine or server
   └─ Example: PORT=3000, DB_URL=mongodb://..., JWT_SECRET=abc123

📄 .env-sample (or .env.example)
   ├─ Purpose: Template for what .env should contain
   ├─ Contains: Same keys as .env but NO VALUES
   ├─ Example:
   │  PORT=
   │  DB_URL=
   │  JWT_SECRET=
   ├─ MUST BE COMMITTED to git
   ├─ Helps developers know what env vars are needed
   └─ Copy this file to .env and add actual values

📄 .prettierrc
   ├─ Purpose: Prettier code formatter configuration
   ├─ Contains formatting rules:
   │  • singleQuote: false → Use double quotes
   │  • bracketSpacing: true → Add spaces in objects { x: 1 }
   │  • tabWidth: 2 → Use 2 spaces for indentation
   │  • semi: true → Add semicolons at end of lines
   │  • trailingComma: "es5" → Add trailing commas where valid in ES5
   ├─ Ensures consistent code style across project
   ├─ Can be JSON, YAML, JS, or TOML format
   └─ Runs on save (if configured in VS Code)

📄 .prettierignore
   ├─ Purpose: Files/folders to exclude from Prettier formatting
   ├─ Contains:
   │  • /.vscode (VS Code config)
   │  • /node_modules (packages)
   │  • dist/ (build output)
   │  • .env (environment files)
   ├─ Prettier won't format these files
   ├─ Saves processing time
   └─ Syntax similar to .gitignore

SRC FOLDER FILES:

📄 src/index.js
   ├─ Purpose: Server entry point (starts the application)
   ├─ Responsibilities:
   │  • Load environment variables (dotenv.config())
   │  • Import the Express app from app.js
   │  • Create HTTP server
   │  • Connect to database
   │  • Listen on a port
   ├─ Example content:
   │  import dotenv from 'dotenv';
   │  import app from './app.js';
   │  
   │  dotenv.config();
   │  const PORT = process.env.PORT || 3000;
   │  app.listen(PORT, () => {
   │    console.log(`Server running on port ${PORT}`);
   │  });
   └─ Run with: npm start (production) or npm run dev (development)

📄 src/app.js
   ├─ Purpose: Express app configuration and setup
   ├─ Responsibilities:
   │  • Create Express app instance
   │  • Register global middleware
   │  • Register routes
   │  • Register error handling middleware
   │  • Export the app
   ├─ Should NOT contain:
   │  • app.listen() (that's in index.js)
   │  • Server startup logic
   ├─ Example content:
   │  import express from 'express';
   │  import userRoutes from './routes/userRoutes.js';
   │  
   │  const app = express();
   │  app.use(express.json());
   │  app.use('/api/users', userRoutes);
   │  
   │  export default app;
   └─ This keeps server logic separate from configuration

📄 src/constants.js
   ├─ Purpose: Store constant values used throughout the app
   ├─ Contains:
   │  • Database collection names
   │  • HTTP status codes
   │  • Error messages
   │  • Regex patterns
   │  • Magic numbers
   │  • Configuration constants
   ├─ Example:
   │  export const HTTP_STATUS = {
   │    OK: 200,
   │    CREATED: 201,
   │    BAD_REQUEST: 400,
   │    NOT_FOUND: 404,
   │  };
   │  
   │  export const ERROR_MESSAGES = {
   │    USER_NOT_FOUND: 'User not found',
   │    INVALID_EMAIL: 'Invalid email format',
   │  };
   └─ Avoids magic numbers/strings scattered in code

4. DIRECTORY-BY-DIRECTORY PURPOSE
================================================================================

📁 src/controllers/
   ├─ Purpose: Business logic and request handling
   ├─ What goes here:
   │  • Functions that handle HTTP requests
   │  • Processing data from requests
   │  • Calling model methods to fetch/save data
   │  • Determining appropriate responses
   │  • Error handling specific to routes
   ├─ File naming: <resource>Controller.js
   │  • userController.js
   │  • productController.js
   │  • orderController.js
   ├─ Example:
   │  export const getUser = async (req, res) => {
   │    try {
   │      const user = await User.findById(req.params.id);
   │      res.json({ success: true, data: user });
   │    } catch (error) {
   │      res.status(500).json({ success: false, error: error.message });
   │    }
   │  };
   └─ Controllers must not directly talk to database (use models)

📁 src/routes/
   ├─ Purpose: API endpoint definitions
   ├─ What goes here:
   │  • URL paths/endpoints
   │  • HTTP method mappings
   │  • Route handlers (references to controllers)
   │  • Route-specific middleware
   │  • Input validation
   ├─ File naming: <resource>Routes.js
   │  • userRoutes.js
   │  • productRoutes.js
   │  • authRoutes.js
   ├─ Should be thin (delegate to controllers)
   ├─ Example:
   │  import express from 'express';
   │  import { getUser, createUser } from '../controllers/userController.js';
   │  
   │  const router = express.Router();
   │  
   │  router.get('/:id', getUser);
   │  router.post('/', createUser);
   │  
   │  export default router;
   └─ Use in app.js: app.use('/api/users', userRoutes);

📁 src/models/
   ├─ Purpose: Database schema definitions and data models
   ├─ What goes here:
   │  • Data schemas (if using MongoDB with Mongoose)
   │  • Database queries
   │  • Data validation at model level
   │  • Database relationships/associations
   │  • Helper methods for data operations
   ├─ File naming: <Entity>.js (singular, capitalized)
   │  • User.js
   │  • Product.js
   │  • Order.js
   ├─ Example (with Mongoose):
   │  import mongoose from 'mongoose';
   │  
   │  const userSchema = new mongoose.Schema({
   │    name: { type: String, required: true },
   │    email: { type: String, unique: true },
   │    password: String,
   │  });
   │  
   │  export default mongoose.model('User', userSchema);
   └─ Controllers use these to interact with database

📁 src/middlewares/
   ├─ Purpose: Functions that process requests before reaching routes
   ├─ What goes here:
   │  • Authentication middleware (check JWT tokens)
   │  • Authorization middleware (check permissions)
   │  • Input validation middleware
   │  • Logging middleware
   │  • Error handling middleware
   │  • CORS configuration
   │  • Rate limiting
   ├─ File naming: <purpose>Middleware.js
   │  • authMiddleware.js
   │  • errorMiddleware.js
   │  • validationMiddleware.js
   ├─ Example:
   │  export const authenticate = (req, res, next) => {
   │    const token = req.headers.authorization?.split(' ')[1];
   │    if (!token) return res.status(401).json({ error: 'No token' });
   │    
   │    try {
   │      req.user = verifyToken(token);
   │      next();
   │    } catch (error) {
   │      res.status(401).json({ error: 'Invalid token' });
   │    }
   │  };
   └─ Use: app.use(authenticate) or router.get('/', authenticate, handler)

📁 src/utils/
   ├─ Purpose: Reusable utility/helper functions
   ├─ What goes here:
   │  • Helper functions used across the app
   │  • Data formatting functions
   │  • Validation functions
   │  • Email sending utilities
   │  • File handling utilities
   │  • Date/time utilities
   │  • API response formatting
   ├─ File naming: <functionality>Utils.js or <functionality>Helper.js
   │  • validationUtils.js
   │  • emailUtils.js
   │  • dateUtils.js
   ├─ Example:
   │  export const formatUserResponse = (user) => ({
   │    id: user._id,
   │    name: user.name,
   │    email: user.email,
   │  });
   │  
   │  export const isValidEmail = (email) => {
   │    return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);
   │  };
   └─ Should be pure functions (no side effects)

📁 src/db/
   ├─ Purpose: Database connection and configuration
   ├─ What goes here:
   │  • Database connection setup
   │  • Connection pooling configuration
   │  • Database initialization
   │  • Database utilities (if needed)
   ├─ File naming: Usually connection.js or config.js
   │  • connection.js
   │  • dbConfig.js
   ├─ Example:
   │  import mongoose from 'mongoose';
   │  
   │  export const connectDB = async () => {
   │    try {
   │      await mongoose.connect(process.env.DB_URL);
   │      console.log('Database connected');
   │    } catch (error) {
   │      console.error('DB connection failed:', error);
   │      process.exit(1);
   │    }
   │  };
   └─ Called from index.js on server startup

📁 public/
   ├─ Purpose: Static files served by the backend
   ├─ What goes here:
   │  • Images
   │  • CSS files
   │  • JavaScript files (frontend, if needed)
   │  • Documents
   │  • Other static assets
   ├─ Served with: app.use(express.static('public'))
   ├─ Access: http://localhost:3000/filename.ext
   └─ Not needed if frontend is separate

📁 public/temp/
   ├─ Purpose: Temporary files storage
   ├─ What goes here:
   │  • Uploaded files during processing
   │  • Cache files
   │  • Temporary data
   ├─ Should be cleared periodically
   └─ Add to .gitignore to avoid committing temp files

📁 node_modules/
   ├─ Purpose: Auto-installed package directory
   ├─ Contains: All npm packages and dependencies
   ├─ Auto-generated by: npm install
   ├─ DO NOT COMMIT to git (in .gitignore)
   ├─ IGNORE entirely (never edit files here)
   └─ Regenerated on: npm install (on any machine)

5. PRETTIER CONFIGURATION (.prettierrc & .prettierignore)
================================================================================

WHAT IS PRETTIER?
────────────────
Prettier is an opinionated code formatter that automatically formats your code
to follow consistent style rules. It helps maintain code consistency across a team
without debates about style.

YOUR .prettierrc CONFIGURATION:
──────────────────────────────

{
  "singleQuote": false,      ← Use double quotes ("text")
  "bracketSpacing": true,    ← Add spaces in objects { x: 1 }
  "tabWidth": 2,             ← Indent using 2 spaces
  "semi": true,              ← Add semicolons at end of statements
  "trailingComma": "es5"     ← Add trailing commas where valid in ES5
}

DETAILED EXPLANATION:

1. singleQuote: false
   ├─ FALSE (your setting): Use double quotes
   │  ✅ const name = "John";
   │  ❌ const name = 'John';
   └─ TRUE: Use single quotes
      ✅ const name = 'John';
      ❌ const name = "John";

2. bracketSpacing: true
   ├─ TRUE (your setting): Add spaces around braces
   │  ✅ const obj = { x: 1, y: 2 };
   │  ❌ const obj = {x: 1, y: 2};
   └─ FALSE: No spaces around braces
      ✅ const obj = {x: 1, y: 2};
      ❌ const obj = { x: 1, y: 2 };

3. tabWidth: 2
   ├─ Number of spaces per indentation level
   │  tabWidth: 2 →  if (true) {
   │                    console.log('test');
   │                  }
   │
   │  tabWidth: 4 →  if (true) {
   │                      console.log('test');
   │                  }
   └─ Your setting: 2 spaces (recommended for JavaScript)

4. semi: true
   ├─ TRUE (your setting): Add semicolons
   │  ✅ const x = 5;
   │  ❌ const x = 5
   └─ FALSE: Remove semicolons (optional)
      ✅ const x = 5
      ❌ const x = 5;

5. trailingComma: "es5"
   ├─ "es5": Add trailing commas where valid in ES5
   │  ✅ const arr = [1, 2, 3,];        // Valid ES5
   │  ✅ const obj = { x: 1, y: 2, };   // Valid ES5
   │  ❌ const arr = [1, 2, 3];         // Missing trailing comma
   ├─ Other options:
   │  • "none": No trailing commas
   │  • "all": Add everywhere possible (ES2017+)
   │  • "es5": Only where valid in ES5 (your setting)
   └─ Useful for git diffs (only new items added show as changed)

YOUR .prettierignore:
────────────────────

/.vscode               ← Ignore VS Code settings folder
/node_modules          ← Ignore installed packages
./dist                 ← Ignore build output (note: should be /dist)

*.env                  ← Ignore all .env files
.env                   ← Ignore .env specifically
.env.*                 ← Ignore all variations (.env.local, .env.test)

WHAT DOES .prettierignore DO?
─────────────────────────────
• Files/folders listed here are NOT formatted by Prettier
• Syntax is similar to .gitignore
• Prettier skips these files entirely (saves processing time)
• Common ignores:
  - node_modules/ (huge, unnecessary to format)
  - dist/ (generated files)
  - .env files (configuration)
  - build/ (generated files)
  - coverage/ (test coverage)
  - *.min.js (minified files)

HOW PRETTIER WORKS:
───────────────────
1. You write code (inconsistent style)
2. Prettier reads your code
3. Prettier applies formatting rules from .prettierrc
4. All code formatted consistently

PRETTIER SETUP:
───────────────
Installation: Already done (in devDependencies)
npm install --save-dev prettier

Format single file:
npx prettier --write src/app.js

Format entire src/:
npx prettier --write src/

Check without changing (dry run):
npx prettier --check src/

VS CODE INTEGRATION:
• Install "Prettier" extension
• Format on save enabled in settings
• Automatically formats when you save a file

WHY USE PRETTIER?
─────────────────
✓ No style debates (opinionated = standardized)
✓ Consistent code across team
✓ Saves manual formatting time
✓ Catches some errors (missing semicolons, etc.)
✓ Works with other tools (ESLint, etc.)
✓ Forces consistency without effort

SEPARATION OF CONCERNS PRINCIPLE:
═════════════════════════════════

Each file/folder should do ONE thing well:

❌ BAD - Mixed concerns:
export const createUser = async (req, res) => {
  const hashedPassword = bcrypt.hashSync(req.body.password);
  const newUser = await db.connection.query(
    "INSERT INTO users VALUES (...)"
  );
  await sendWelcomeEmail(newUser.email);
  res.json(newUser);
};

✅ GOOD - Separated concerns:
// userController.js
export const createUser = async (req, res) => {
  const user = await User.create(req.body);
  await emailService.sendWelcome(user.email);
  res.status(201).json(user);
};

// userModel.js
export const create = async (userData) => {
  const hashedPassword = await hashPassword(userData.password);
  return User.create({ ...userData, password: hashedPassword });
};

// emailService.js (in utils/)
export const sendWelcome = async (email) => {
  await emailClient.send({ to: email, template: 'welcome' });
};

ERROR HANDLING PATTERN:
══════════════════════

✅ GOOD:
try {
  const user = await User.findById(id);
  if (!user) {
    return res.status(404).json({ error: "User not found" });
  }
  res.json(user);
} catch (error) {
  res.status(500).json({ error: error.message });
}

❌ BAD:
const user = await User.findById(id);
res.json(user);  // Crashes if user is null

│ .prettierrc             │ Code formatting rules                      │
│ .prettierignore         │ Files to skip formatting                   │

│ controllers/            │ Request handlers & business logic          │

│ models/                 │ Database schemas & queries                 │
│ middlewares/            │ Request processing (auth, validation)      │
│ utils/                  │ Helper & utility functions                 │
│ db/                     │ Database connection setup                  │
│ public/                 │ Static files (images, CSS, etc.)           │
│ node_modules/           │ Installed packages (IGNORE)                │
└─────────────────────────┴────────────────────────────────────────────┘

PRIORITY RULES:
1. Controllers are thin → Delegate to models/utils
2. Models handle database → No HTTP logic in models
3. Routes are routing → No business logic in routes
4. Middlewares are reusable → Apply to multiple routes
5. Utils are pure → No side effects, just functions
6. Constants are immutable → Use for magic values/strings

TYPICAL REQUEST FLOW:
1. Client sends HTTP request
2. Middleware processes it (authentication, validation)
3. Routes direct to correct controller
4. Controller gets data from model
5. Controller sends response to client

GIT WORKFLOW:
✓ git add .gitignore first (before any secrets)
✓ git add package.json + package-lock.json
✓ git add .prettierrc, README.md, .env-sample
✓ NEVER: git add node_modules/ or .env
✓ Always: git pull before working
✓ Always: npm install after git pull

COMMON COMMANDS:
npm start                 → Production start
npm run dev             → Development with auto-restart
npm install             → Install dependencies
npx prettier --write .  → Format entire project
npm install <package>   → Add new dependency
npm install -D <package>→ Add dev dependency
