1. WHAT IS NODE.JS?
================================================================================

Node.js is a JavaScript runtime built on Chrome's V8 JavaScript engine that 
allows you to run JavaScript code outside the browser, specifically on servers 
and computers.

KEY FEATURES:
• Event-driven, non-blocking I/O model
• JavaScript on the backend (same language as frontend)
• Great for building scalable network applications
• Single-threaded but asynchronous (uses callbacks/promises/async-await)
• Can handle multiple concurrent connections efficiently

WHAT IT ENABLES:
- Building server-side applications (APIs, webservers)
- File system operations
- Database connections
- Building real-time applications
- Command-line tools and scripts

INSTALLATION:
Visit nodejs.org and download the LTS (Long Term Support) version.
Verify installation: node --version && npm --version

2. WHAT IS NPM (Node Package Manager)?
================================================================================

npm is the default package manager for Node.js. It helps you manage libraries 
and dependencies in your projects.

KEY RESPONSIBILITIES:
• Install third-party packages/libraries
• Manage project dependencies
• Run scripts defined in package.json
• Manage versions of packages
• Share and publish packages

COMMON npm COMMANDS:
npm init              → Initialize a new project (creates package.json)
npm install           → Install all dependencies listed in package.json
npm install <package> → Install a specific package
npm install -D <pkg>  → Install as development dependency
npm uninstall <pkg>   → Remove a package
npm list              → See all installed packages
npm start             → Run the "start" script from package.json

PACKAGE.JSON:
The package.json file is the heart of your Node.js project. It contains:
- Project metadata (name, version, description)
- List of dependencies (production and development)
- Scripts for running your project
- Entry point (main file)

3. WHAT IS EXPRESS.JS?
================================================================================

Express is a minimal and flexible Node.js web application framework that 
provides a set of features for building web applications and APIs.

WHY USE EXPRESS?
• Simplifies HTTP request handling
• Provides routing capabilities
• Middleware support for processing requests
• Easier error handling
• Lightweight compared to other frameworks

CORE CONCEPTS:
• Routes: Define how your application responds to HTTP requests
• Middleware: Functions that have access to request/response objects
• HTTP Methods: GET, POST, PUT, DELETE, PATCH
• Port: The network socket your server listens on (e.g., 3000, 8000)

BASIC EXPRESS STRUCTURE:
const express = require('express');
const app = express();

// Middleware
app.use(express.json());

// Routes
app.get('/', (req, res) => {
  res.send('Hello World!');
});

// Listen on port
app.listen(3000, () => {
  console.log('Server running on port 3000');
});

KEY EXPRESS METHODS:
app.get('url', callback)      → Handle GET requests
app.post('url', callback)     → Handle POST requests
app.put('url', callback)      → Handle PUT requests
app.delete('url', callback)   → Handle DELETE requests
app.listen(port, callback)    → Start the server
app.use(middleware)           → Use middleware

HTTPS (Requires Setup):

const express = require('express');
const https = require('https');
const fs = require('fs');
const app = express();

app.get('/', (req, res) => {
  res.json({ message: 'Hello' });
});

// Load SSL/TLS certificates
const options = {
  key: fs.readFileSync('path/to/private-key.pem'),
  cert: fs.readFileSync('path/to/certificate.pem')
};

// Create HTTPS server with Express
https.createServer(options, app).listen(443, () => {
  console.log('Server running on https://localhost:443');
});

4. INITIALIZING A BACKEND PROJECT
================================================================================

STEP-BY-STEP PROCESS:

STEP 1: Create a project directory
  mkdir my-backend-project
  cd my-backend-project

STEP 2: Initialize npm
  npm init
  (This creates package.json - you'll be asked various questions)
  Use: npm init -y (to skip questions and use defaults)

STEP 3: Install Express and other dependencies
  npm install express
  npm install -D nodemon     (Install nodemon as dev dependency)
  npm install dotenv         (For environment variables)

STEP 4: Create the main file (e.g., server.js or index.js)
  Create a file: touch server.js

STEP 5: Set up .env file
  touch .env
  Add your environment variables here

STEP 6: Update package.json scripts
  "scripts": {
    "start": "node server.js",
    "dev": "nodemon server.js"
  }

STEP 7: Start developing!
  npm run dev   (During development)

5. UNDERSTANDING PACKAGE.JSON SCRIPTS
================================================================================

Scripts in package.json are commands you can run from the terminal using npm.
They are shortcuts to node commands and automation tasks.

YOUR PROJECT EXAMPLE:
"scripts": {
  "test": "echo \"Error: no test specified\" && exit 1",
  "start": "node index.js"
}

The "start" script:
- Command: npm start or npm run start
- What it does: Runs 'node index.js' to start your server
- Output: Server starts and begins listening for requests

COMMON SCRIPTS:
"start": "node server.js"           → Start production server
"dev": "nodemon server.js"          → Start dev server with auto-reload
"test": "jest"                      → Run tests
"build": "webpack"                  → Build/compile your project
"serve": "node build/server.js"     → Serve built project
"lint": "eslint ."                  → Check code quality

WHY USE SCRIPTS?
• Consistency: Same command regardless of OS differences
• Simplicity: Easy to remember and run
• Automation: Can automate complex tasks
• Team standardization: All developers use same commands

HOW TO RUN SCRIPTS:
npm run <script-name>    → Run any script
npm start                → Special shortcut for "start" script
npm test                 → Special shortcut for "test" script

6. NODEMON - DEVELOPMENT HELPER
================================================================================

Nodemon is a tool that automatically restarts your Node.js application 
whenever file changes are detected during development.

WITHOUT NODEMON:
1. Make code change
2. Stop server (Ctrl+C)
3. Run npm start again
4. Repeat...

WITH NODEMON:
1. Make code change
2. Automatically detects change
3. Restarts server instantly
4. Continue development

INSTALLATION:
npm install -D nodemon   (Install as development dependency)

USAGE:
Instead of: npm start (uses 'node index.js')
Use: npm run dev  (uses 'nodemon index.js')

Update your package.json:
"scripts": {
  "start": "node index.js",
  "dev": "nodemon index.js"
}

BENEFITS:
• Saves development time
• No need to manually restart
• Instant feedback on code changes
• Better development experience

WHY AS DEV DEPENDENCY?
Nodemon is only needed during development, not in production.
Using -D (--save-dev) ensures it's not shipped with your production code.

7. .ENV FILES AND ENVIRONMENT VARIABLES
================================================================================

A .env file stores sensitive configuration and environment-specific settings
that should NOT be committed to version control.

WHAT GOES IN .ENV:
• Database credentials
• API keys/secrets
• Port numbers
• Third-party API keys
• JWT secrets
• Passwords

EXAMPLE .ENV FILE:
PORT=3000
DATABASE_URL=mongodb://localhost:27017
API_KEY=your_secret_key_here
JWT_SECRET=your_jwt_secret
NODE_ENV=development
EMAIL_PASSWORD=your_email_password

HOW TO USE .ENV:
1. Create a .env file in your project root
2. Install dotenv: npm install dotenv
3. Load it at the very top of your main file:
   
   require('dotenv').config();
   
4. Access variables using process.env:
   
   const port = process.env.PORT || 3000;
   const dbUrl = process.env.DATABASE_URL;
   const apiKey = process.env.API_KEY;

SECURITY BEST PRACTICES:
• NEVER commit .env to git (add to .gitignore)
• Create .env.example with placeholder values
• Never hardcode secrets in code
• Restrict access to .env files
• Use different values for development and production
• Rotate keys and secrets regularly

.GITIGNORE ENTRY:
Add this to your .gitignore file:
.env
.env.local
.env.*.local

8. BACKEND PROJECT STRUCTURE (BEST PRACTICES)
================================================================================

SIMPLE STRUCTURE (Small Projects):
my-backend/
├── node_modules/           (All installed packages - don't commit)
├── .env                     (Environment variables - don't commit)
├── .gitignore              (Git ignore rules)
├── package.json            (Project metadata & dependencies)
├── package-lock.json       (Locked versions - do commit)
├── server.js               (Main entry point)
├── routes/                 (All route definitions)
│   ├── users.js
│   ├── products.js
│   └── orders.js
├── controllers/            (Business logic)
│   ├── userController.js
│   ├── productController.js
│   └── orderController.js
├── models/                 (Database models/schemas)
│   ├── User.js
│   ├── Product.js
│   └── Order.js
├── middleware/             (Custom middleware functions)
│   ├── auth.js
│   └── errorHandler.js
└── utils/                  (Helper functions)
    ├── database.js
    └── validators.js

FOLDER EXPLANATIONS:

node_modules/
- Contains all installed packages
- Auto-generated by npm
- Never commit to git

routes/
- Defines URL paths and HTTP methods
- Should be thin and delegate to controllers
- Example: app.get('/users/:id', controller.getUser)

controllers/
- Contains business logic
- Handles request processing
- Interacts with models and services
- Example: Fetch user data, process it, send response

models/
- Defines data structure and schema
- Interacts with database
- Contains validation logic if using ODM/ORM

middleware/
- Functions that process requests before reaching routes
- Authentication, validation, logging, etc.
- Can modify request/response objects

utils/
- Helper/utility functions used across the app
- Database connections, validators, etc.
- Reusable code

WHY THIS STRUCTURE?
✓ Separation of concerns
✓ Easy to maintain and scale
✓ Easy to test
✓ Easy to find code
✓ Follows industry standards
✓ Scalable as project grows

9. BASICS OF EXPRESS.JS - PRACTICAL EXAMPLE
================================================================================

YOUR CURRENT PROJECT (1_BackEnd_Deploy):

FILE: index.js
This is the entry point where Express starts your server.

BASIC EXPRESS SETUP:
const express = require('express');
const app = express();

// Middleware to parse JSON
app.use(express.json());

// Routes
app.get('/', (req, res) => {
  res.json({ message: 'Hello World!' });
});

app.get('/users/:id', (req, res) => {
  const userId = req.params.id;
  res.json({ message: `User ${userId}` });
});

app.post('/users', (req, res) => {
  const userData = req.body;
  // Process user data
  res.json({ success: true, data: userData });
});

// Error handling
app.use((err, req, res, next) => {
  console.error(err);
  res.status(500).json({ error: 'Internal Server Error' });
});

// Start server
const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});

REQUEST OBJECT (req):
• req.body     → Data sent in request body (JSON, form data)
• req.params   → URL parameters (/users/:id → req.params.id)
• req.query    → Query string (?search=value → req.query.search)
• req.headers  → HTTP headers
• req.method   → HTTP method (GET, POST, etc.)

RESPONSE OBJECT (res):
• res.json()   → Send JSON response
• res.send()   → Send text/HTML response
• res.status() → Set HTTP status code
• res.redirect()→ Redirect to another URL
• res.end()    → End response without data

MIDDLEWARE:
Middleware are functions that execute during request/response cycle.

Example - Logging middleware:
app.use((req, res, next) => {
  console.log(`${req.method} ${req.path}`);
  next(); // Pass control to next middleware/route
});

Example - Authentication middleware:
const auth = (req, res, next) => {
  const token = req.headers.authorization;
  if (!token) return res.status(401).json({ error: 'No token' });
  // Verify token
  next();
};

// Use middleware on specific route
app.get('/protected', auth, (req, res) => {
  res.json({ message: 'Protected route' });
});

HTTP METHODS IN EXPRESS:

GET - Retrieve data
app.get('/api/users', (req, res) => {
  res.json({ users: [...] });
});

POST - Create new data
app.post('/api/users', (req, res) => {
  const newUser = req.body;
  res.json({ success: true, user: newUser });
});

PUT - Update entire resource
app.put('/api/users/:id', (req, res) => {
  const updateData = req.body;
  res.json({ success: true, updated: updateData });
});

DELETE - Delete resource
app.delete('/api/users/:id', (req, res) => {
  res.json({ success: true, message: 'User deleted' });
});

PATCH - Update partial resource
app.patch('/api/users/:id', (req, res) => {
  const partialUpdate = req.body;
  res.json({ success: true, updated: partialUpdate });
});

STATUS CODES:
200 - OK (Success)
201 - Created (Resource created successfully)
400 - Bad Request (Invalid input)
401 - Unauthorized (Authentication required)
403 - Forbidden (No permission)
404 - Not Found (Resource doesn't exist)
500 - Server Error
